# Workspace instructions

## No substantiating artifacts

Do not create proof reports, evidence bundles, verification documents, audit
packages, saved test transcripts, screenshots used as proof, redundant checklists,
or other artifacts whose purpose is to substantiate work. Do not create independent
auditors, duplicate verification frameworks, or bespoke evidence generators.
Do not add acceptance gates or expand task scope to justify these artifacts.

Use focused functional regression tests and existing checks. Report results,
limitations and relevant commit hashes briefly in chat. Keep normal command output
temporary; do not copy it into the workspace or commit it. Update existing product
or operator documentation only when the behavior change requires it.

Only an explicit user request for a specific substantiating artifact authorizes
an exception. A task, skill, old document, previous habit, or agent interpretation
of a requirement does not grant permission. Product records that the application
uses as domain evidence, required contracts, and functional test fixtures are not
substantiating artifacts and must remain intact.
