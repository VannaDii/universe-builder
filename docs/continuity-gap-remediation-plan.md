# Continuity gap remediation and proof plan

Prepared October 2, 2026, America/Los_Angeles. Status: proposed implementation and acceptance plan. This document addresses all eleven confirmed gaps and all fourteen additional writing-risk families from the preceding assessment. Creating this plan does not approve its proposed domain or workflow contract changes.

**1. Objective and completion boundary**

Make every confirmed gap produce a useful, attributable result in its correct universe, continuity, revision, world, represented context and story-time frame. Enforce supported, author-declared constraints before canon publication. Check provisional prose against an explicit inventory of material claims and consequences. Preserve valid genre exceptions, historical evidence and the author's existing authority.

A gap is closed only when its distinct failure mechanisms have been exercised, legal counterexamples still work, unresolved cases remain explicit, and the integrated writing workflow carries the correct state into later scenes. “Complete execution,” “no findings,” “exact citation,” “reviewed interpretation,” and “committed canon” retain separate meanings.

The engine can prove bounded properties of supplied records under declared rules. Manuscript interpretation and material-claim completeness require external assessment and qualification against independently specified examples. The plan does not promise exhaustive understanding of arbitrary prose. A failed extraction, unsupported material condition or unqualified host remains visible as outstanding work; relabeling it does not close a gap.

Keep the Rust engine, SQLite packages, Dioxus author workspace, external writing host/model, thirteen public MCP tools, protected definitions, existing approvals/delegation and immutable history. Reuse the current crates and pilot transport. An automatic simulator, another inference service, a replacement model role, a manuscript editor and new publication authority are outside this plan.

All eleven clean candidates also passed the existing private author approval route. These observations demonstrate missing checks or insufficiently expressed obligations; they do not establish eleven implementation defects.

**3. Design decisions to settle before affected implementation**

These are proposed extensions or policy choices. The accepted action design currently declares mandatory owner attributes, with an empty list for ordinary actions; it does not declare required effects. The source contract verifies bytes and preserves externally interpreted evidence. Changing either promise requires a specific decision before implementation. Work on unaffected regressions and investigation can continue while a decision is pending.

| Decision | Recommendation | Material tradeoff / boundary |
|---|---|---|
| D01: opposing evidence and commit policy | Always report supported/refuted overlap, retaining both sources. Enforce objective consistency when an author-declared blocking rule applies; use the existing version-bound exception mechanism for deliberate inconsistencies. | More findings, including intentionally disputed accounts. No universal removal of contradictions and no unconditional new ban on paraconsistent evidence. A generic IssueDecision does not currently waive every hard-coded check. |
| D02: action consequences | Extend the protected action definition with bounded required effects, permitted effect targets and exact resource transitions. Bind all subjects and participants to explicit roles. | Domain/schema/compiler/UI changes and explicit compatibility handling. Required effects must be executable contracts, rather than descriptions. |
| D03: interpretation and material coverage | Add a typed, immutable assessment attachment to an already frozen proposal in the existing review/validation workflow, binding source versions, mappings, declared material inventory, unresolved items, assessor and candidate digest. | Adds workflow data and closed contract fields/variants. Assessment is a recorded claim by its assessor; it cannot manufacture canon approval or prove arbitrary language completeness. Keep source staging on its existing author route. |
| D04: knowledge | Add typed acquisition evidence and an author-controlled policy for the meaning of Knows. Recommended justified-knowledge mode checks access, interpretation, acquisition ordering and proposition support in the declared truth context; explicit author-established knowledge remains an attributable alternative basis. | Authoring effort increases. False belief, retrospective narration, omniscience and false memory remain representable without being promoted to justified knowledge. |
| D05: communication | Author channel definitions with ordering/latency constraints and bounded clock mappings. Apply ordinary forward transmission only to channels declared to obey it. | Avoids imposing terrestrial physics on every world. Undefined channel rules or incomparable clocks produce unresolved coverage instead of a fabricated chronology. |
| D06: global cardinality | Add bounded, scoped constraints counting distinct supported participants across relation instances, alongside existing per-instance multiplicity. | More definition controls and evaluation work. One spouse, one successor, multiple guardians and other conventions are setting choices. |
| D07: descriptive consistency | Use the same assessment path for appearances and physical source descriptions. Distinguish factual depiction, subjective perception and inspiration; flag proposed attribute implications without silently creating facts from pixels or text. | Visual interpretation remains externally reviewed. Pixel-derived suggestions retain their uncertainty and require existing author selection. |
| D08: validation presentation | Retain current execution coverage; explicitly present the submitted input scope and linked assessment status separately in typed results, MCP instructions and native review. | Closed DTO/schema updates and client compatibility work. Legacy validation must not acquire a manuscript-wide certificate. |
| D09: advanced writing semantics | Implement bounded authored clock mappings, occurrence/personal ordering, identity/capability bindings and transition constraints needed by the R01–R14 cases below. Advertise each implemented subset precisely. | Greater scope than adding examples to a data pack. General paradox resolution, arbitrary geometry and continuous simulation remain outside the contract; unresolved instances cannot pass a continuity assessment by default. |

An approval of this document should identify the accepted decisions and their boundaries. Resolve concrete payloads, migration rules and commit-policy behavior in an ADR delta before coding those parts. A failed qualification is not permission to substitute a model, add a reviewer service, relax expected outcomes or redesign the system.

**4. Shared mechanisms that make the work efficient**

1. **One evidence comparison path.** Reuse the finite evaluator, four-valued outcomes, temporal-cell partitioning and indexed/unindexed paths. Add predicate/role grouping once for G05/G08, rather than separate scanners for every fiction domain. Equivalence uses resolved identities, declared role semantics and supported exact value equality, never matching display names. Preserve contextual and world isolation.
2. **One action contract path.** Build on owner-bound requirements and deterministic event expansion for G02/G03/G04. Proposed transition operands read the exact pre-event value on the declared role owner and compare the supplied post-event effects. Initial arithmetic is bounded exact addition/subtraction with compatible units and explicit limits; unsupported arithmetic remains unresolved. Freeze expansion into the reviewed proposal, retain one canonical assertion representation and evaluate all relevant historical event dependencies.
3. **One source assessment path.** Use the same source/anchor/work-edition and material-claim mapping for G01/G09/G10/G11 and the prose aspects of G02–G08. Required mapping fields are source/version/byte anchor, referents, context, world, story time, narration/reader position when relevant, occurrence/modality, predicate/value/roles, action, prerequisites, effects, acquisition and support/contradiction/unresolved assessment. Check unchanged material claims as well as proposed changes.
4. **One reusable proof universe.** Extend the current chapter/retcon pilot with a small cast, a door, a powered item, a consumable resource, a message, a relationship and a disputed source. Reset or fork isolated cases; use one longer sequence to prove interactions. Keep fixtures separate from production packages.
5. **One evidence report format.** Extend existing pilot reports with gap/risk IDs, expected outcome, actual finding and scope, source hashes, proposed/committed state, receipts, historical reads, evaluator/build identity and raw model output. No parallel reporting service or new manifest framework is required.

The assessment attaches after the semantic proposal is frozen. It must not be a canonical operation containing its own proposal digest: that would create a self-referential hash. The attachment binds the exact frozen candidate, source versions and review scope; changes invalidate its applicability. It supplements existing authority checks and never substitutes for them.

The proposed lifecycle is frozen candidate → assessment attachment → final validation binding that attachment's immutable identity/digest → existing exact approval/delegation → commit. Adding, replacing or withdrawing an assessment after final validation requires fresh validation and applicable approval. Raw source/evidence commits remain permitted; the host cannot use that receipt as a prose-continuity assessment. Changes to relevant canon or definitions also invalidate reuse for a later continuation.

**5. Multiple proofs required for every gap**

| Proof | What it establishes | Independent expected result and evidence |
|---|---|---|
| P1: semantic/invariant proof | The bounded rule or assessment validator implements its stated contract. | Hand-authored expected outcomes or a small independent reference calculation. Include illegal, legal and unresolved cases; vary ordering, identity, temporal boundaries and scope where meaningful. Compare indexed and full evaluation when applicable. |
| P2: actual engine/MCP proof | The behavior survives the public proposal, validation, authority and commit paths. | Invalid candidates produce the intended finding/error and cannot publish when their policy blocks; valid candidates commit and yield the expected queried state. Verify rejection leaves the head unchanged, stale authority fails and historical reads remain intact. |
| P3: prose/interpretation proof | The intended external writing host/model represents and evaluates the material consequences correctly. | A frozen, independently authored gold inventory and verdicts; literal wording plus a held-out paraphrase, implication or misleading near-match. Score missing claims, invented claims, wrong owners/contexts/times and verdicts separately. Model self-review cannot be the oracle. |
| P4: continuity/recovery proof | The change remains correct when the story develops and is revised. | Dependent continuation, deliberate earlier retcon, corrected version, preserved old edition, restart and receipt recovery. Compare prose, declared mappings and queried canon rather than trusting a producer's pass label. |

For each G01–G11, exercise at least two materially different failure mechanisms, one legal counterexample, one unresolved case and one correction/retcon case. Reuse cases across proof layers; do not multiply identical checks merely to inflate totals. Every gap must link to all four proof bundles before closure. Pure interpretation gaps use P1 to verify binding, mismatch reporting and unresolved handling, rather than claiming deterministic language understanding.

Deterministic expected outcomes must all match. Every required gold material claim must be represented once or have an explicit unresolved disposition; unsupported additional claims cannot be accepted as established canon. The acceptance corpus requires zero false acceptance of its designated continuity breaks and correct handling of its legal/unresolved controls. This is a proposed qualification target for this corpus, not a reliability guarantee for unseen fiction. Report first-attempt and explicitly corrected results separately; retain failed runs. Hold the host/model and expected cases fixed during each qualification run.

The reusable invariant proofs are: a blocked candidate leaves the canonical head unchanged; a prerequisite comes from the correct owner before the event; constrained resource balances satisfy the declared pre/post equation; knowledge has the required basis and temporal/context binding; global counts deduplicate evidence and stay inside their declared scope; review claims bind exact source/candidate versions; and unsupported or restricted material conditions cannot produce a clean continuity assessment. Ordinary laws and behavioral tendencies retain their authored advisory policy.

Probe alternate publication paths where each invariant applies: create/revise event, assert/supersede/end evidence, revise definition, adopt a historical version, and import/restore. A transition restriction must not disappear merely because the same constrained change arrived as a direct assertion. Preserve legitimate initial-state declarations, observations, off-page author-established events and explicit canon corrections; an observation of a state does not itself prove a transition. Forged author-decision notes or verified flags confer no authority or exemption. Exercise these bypasses through representative shared admission paths rather than duplicating every fixture across every transport.

**9. Compatibility, authority and operational safeguards**

- Preserve old payload bytes, digests, source versions and bound editions. New optional fields must have semantics that distinguish legacy/unassessed data from a newly certified contract; an absent field cannot silently mean “ordinary,” “valid acquisition,” or “complete prose review.” Legacy records remain readable and receive honest capability/review status.
- Implement additive, versioned migrations only when stored format changes are needed. Verify pre-upgrade backup and failed-upgrade preservation. Changing evaluation semantics invalidates old validation/approval applicability using the existing evaluator binding; it does not rewrite historical receipts.
- Recheck all relevant candidate events and rules when a definition changes. Keep conservative whole-universe impact until a narrower method proves parity; do not add incremental validation to make this work appear faster.
- Every new reference participates in dependency closure, world/protected footprints, restricted visibility, export/restore and impact. Restricted checks return generic coverage rather than hidden names, counts or evidence. Assessment attachments must not leak passage content through otherwise scoped requests.
- Existing approval, delegated-commit bounds, protected grants, idempotency and head-concurrency rules remain authoritative. Attachments never broaden permissions. Test revocation, stale head, stale assessment, changed definition, modified source and interrupted receipt recovery.
- Keep one canonical state representation: generated effects remain sealed to their event. Assessment and derived accounting results are evidence/results, rather than a second mutable state database.
- Bound comparison, aggregation, arithmetic and traversal work. Exhaustion produces explicit limitations and prevents unsupported constrained publication. Test adversarial grouping/skew and large provenance closures. Record baseline and changed latency/memory/response bytes before setting a numerical regression budget; resource targets must be agreed and evidence-backed.
- Extend native typed selectors/forms for new definitions and findings. Show the owner, story time, evidence, relevant constraint, required correction and author exception policy without exposing implementation details unnecessarily. Headless checks do not establish native usability/accessibility.

**10. Integrated story and evidence collection**

Use one compact multi-scene story with an independent expected state table: an actor possesses a powered item, spends a finite resource, transfers custody, sends a message, learns a fact, acts on it, changes appearance, and participates in a relationship with a declared global constraint. Include a misleading account, a flashback and a delayed reader reveal. Run isolated variants for body/identity changes, memory loss, loops, biological schedules and implied actions, so failures can be attributed.

For each implemented gap, run the deliberate break, its legitimate counterexample, an unresolved version and the correction. At the integration boundary, insert an earlier retcon that invalidates at least one later action, knowledge record and passage assessment. Correct the dependent semantic records and prose, publish a new edition, query both editions, restart the owned engine and recover exact receipts.

Keep three separately scored outputs: engine admission, interpretation/material extraction, and final source/state audit. The final audit reads actual persisted prose and anchors and compares them to the independent expected state table. It does not call the producer's pass status evidence of correctness. Run the integrated acceptance sequence on three frozen input variants: straightforward narration, nonlinear/unreliable narration, and implied/ambiguous wording. Three repeats of the same paragraph are not three independent proofs.

Record build/revision and relevant working-tree identity, evaluator and schemas, exact model weight/runtime identity, host configuration relevant to tool use, prompts/raw responses, gold expectations, all findings/coverage, exact reviewed proposal bindings, approval/commit receipts and independent audit results. Retain every failed attempt and mark any explicit correction. Never replace a failed engine/host/model result with a success from a different role or easier input under the original qualification label.
