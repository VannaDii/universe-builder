# G05 independent oracle and compatibility review

Prepared October 2, 2026. Decision status: **pending Vanna**. This review specifies expected outcomes; it does not approve D01, implement detection, or claim the proposed behavior has passed an engine run.

## Independence and derivation

The reviewing agent inspected the current domain, evidence algebra, finite claim resolver, time algebra, candidate validation, rule exceptions, and approval/commit path before reading the proposed G05 design or its fixture file. The initial oracle below was frozen from those sources and the G05 requirement. It is a separate derivation, not a second execution of the proposed comparison algorithm. A later comparison may annotate discrepancies without changing these initial outcomes to fit a proposal or implementation.

For exact evidence, derive outcomes by taking the intersection of independently stated world sets and half-open time sets, only after establishing identical universe, represented context, realm, and proposition meaning. At each admitted cell set the two evidence bits independently: support only = Supported; refutation only = Refuted; both = Conflicting; neither = NotEstablished. Unresolved applicability is a separate coverage limitation, never a fifth truth value or a reason to discard already established bits.

Notation: P is a particular proposition, `door/open=true`, about one stable entity in objective context C. Unless changed below, evidence is exact, universe-wide, realm absent, on named calendar K, validity [10,20), with distinct assertion versions S and R. P2 has a different proposition record ID but the same meaning. Fixtures concern automatic reporting, independently of rules. “Legal” means the evidence is representable without a newly invented universal blocker; authored rules may independently constrain it.

## Compatibility findings grounded in current code

1. **Four-valued reasoning already preserves opposition.** `crates/universe-rules/src/evidence.rs` stores independent support/refutation bits, and `basic.rs::claim` searches all matching proposition records. A rule consuming a matched claim can already obtain Conflicting across distinct IDs. Automatic reporting is missing because `validation.rs::scalar_conflicts` admits only Support assertions and compares unequal values. G05 must add reporting rather than replace this algebra or equate refuting `open=true` with supporting `open=false`.
2. **Exact identity has a compatibility edge.** `records.rs::Proposition` includes predicate, subject, role bindings, value, quantification and context; raw derived equality includes vector role order. `basic.rs::claim` compares roles without ordering and supported exact values, but its match does not test quantification. A new G05 grouping may properly distinguish quantification while an existing Claim expression still consumes both. Do not silently widen G05 identity to hide this difference or change all existing Claim semantics under D01. Document the limitation and test quantification isolation for the detector.
3. **Context mismatch is not currently rejected as a structural invariant.** Structural validation independently checks that proposition context and assertion scope context name represented contexts. `basic.rs::claim` requires both to equal the evaluation context. A mismatched pair should remain explicitly unresolved/ineligible for exact detection; adding a new universal structural rejection or silently rewriting one context would be an additional policy change.
4. **Temporal conservatism is established.** `scope.rs::Validity` distinguishes Unspecified and Unknown, names calendar intervals, and specifies half-open boundaries. `time.rs::overlaps` returns `None` for unsupported comparisons and special-cases two Unspecified validities as overlap. `rule_checks.rs::frames` partitions named exact intervals at evidence/exception boundaries. The proposed detector must report actual cells without asserting that bounded uncertainty has already been qualified by this exact frame partitioner.
5. **Exceptions target authored rules, not generic findings.** `rule_checks.rs::valid_exception` requires the current exact rule version, a supported target, contained applicability/time, matching realm/context where relevant, nonempty rationale, and an Accept IssueDecision whose scope names that rule. `exception_at` checks each frame/world. `evaluate_indexed` keeps evidence and requires complete evaluation even when waived. G05 must not introduce a generic IssueDecision bypass or erase the opposing evidence when waived.
6. **Author approval is exact authority, not an override of inadmissibility.** `workflow.rs::approve` rejects inadmissible/stale/unsubmitted proposals and stale heads, binding exact proposal and validation evidence. Commit checks current authorization and boundaries, exact validation/evaluator, applicable delegation or approval, current head, then privately rechecks the complete candidate. Delegation requires Complete coverage and allowed, unprotected footprint. New findings do not create authority. The statement that BlockUnlessException “blocks delegated commit” in domain comments is narrower than actual workflow admission: current author approval also fails when checked.admissible is false.
7. **Existing hard checks stay separate.** `workflow.rs::evaluate` unconditionally makes scalar/completeness conflicts or their gaps inadmissible. G05 cannot route those existing checks through a new optional policy or claim an exception waives them. Actions and structural validation can also reject before G05 reporting. Fixture expectations must isolate G05 behavior while compatibility controls prove these checks remain intact.
8. **Visibility applies before result disclosure.** Restricted validation routes return Coverage::Restricted with no findings; commit deliberately performs a private full-scope recheck whose evidence must not be disclosed. Any new conflict identifiers, overlap cells, fingerprints and dependency chains need the same confinement, not just source-text redaction.
9. **Changing results requires explicit compatibility handling.** Existing Finding has a mandatory `rule_id` and flat evidence list; an automatic conflict has no authored rule ID. A typed automatic-conflict result or versioned discriminator is needed rather than pretending a proposition/predicate ID is a policy rule. Preserve canonical stored payloads and historical receipts; evaluator binding must invalidate stale approval applicability. Public closed schema and native finding rendering require review if result shapes change. This is a scoped G05 presentation concern, not permission to implement D08 or D03.

## Proof limits and decision boundary

The gold results above are independent semantic judgments and source-based compatibility findings. They do not demonstrate implemented detection, public MCP admission, native usability, performance, or recovery. Future qualification must execute both failure mechanisms and the legal, unresolved, restricted, correction and policy cases against the approved design, retaining failed attempts. Vanna still decides D01; this review grants no approval and makes no other design decision.

The corrected context handling resolves C3 without expanding structural policy. The bounded NoOpposingEvidence metacondition is a coherent scoped way to express D01: the absence of a pair is a candidate-inspection property, so complete absence yields Supported; a demonstrated pair refutes that property while the underlying proposition remains Conflicting. This is explicit closed-snapshot reasoning about stored evidence, not missing-as-false truth about the fictional world. A definite pair with incomplete remaining inspection retains Refuted and incomplete coverage, matching the current complete-evaluation requirement for blocking rules. NoOpposingEvidence is new rule language pending Vanna's decision; the reviewer does not treat it as implemented.

Temporal extension is necessary and explicitly exposed: current `rule_checks::frames(Unspecified, ...)` returns only the submitted base frame. Candidate validation requires Timeless and generic claim evaluation does not collapse dated evidence there. The proposal correctly calls for both-polarity temporal partitioning even for unqualified rule validity, so an unqualified consistency rule cannot miss earlier finite overlap. This is an implementation target and acceptance obligation, not current supported behavior. Equal explicit realms may be reported directly, but the existing rule evaluator's realm limitation remains visible; no realm inference is smuggled into admission.

The coverage/authority matrix matches the inspected workflow: automatic nonblocking uncertainty can make coverage Partial; delegation then fails its Complete gate; exact author approval remains possible only while admissible. Blocking-rule incompleteness is already inadmissible. Version-bound exceptions preserve evidence and cannot make incomplete evaluation complete. Generic IssueDecision and direct author approval do not waive hard checks. Restricted validation still exposes no findings, and private commit recheck must retain that confidentiality.

The F06 correction is now reflected in the fixture file: one Decimal-shaped predicate with Decimal digits `1.0` and `1.00`. Their current exact comparator representations are 10/10 and 100/100, whose checked cross-products are equal. Both conform to the same existing value shape. The initial F49–F53 table rows also needed the missing column separator before their Additional oracle label; this was corrected and the reviewer confirmed the corrected rows directly.
